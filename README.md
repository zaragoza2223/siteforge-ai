# SiteForge AI — MVP генератора лендингов

Небольшой full-stack проект для портфолио: бриф бизнеса → генерация структуры и текстов через LLM API → предпросмотр → ручное редактирование → экспорт автономного HTML-файла.

## Что уже работает

- React-интерфейс конструктора с формой бизнес-брифа.
- Генерация контента через OpenAI-совместимый API.
- Настройка локального Ollama или удалённого провайдера через `.env`. Для локального Ollama используется нативный `/api/chat`, отключено рассуждение Qwen3 (`think: false`), включён JSON-режим и установлен контекст 8192 токена, чтобы не тратить время на длинное рассуждение перед генерацией JSON.
- Предпросмотр страницы на основе подготовленных блоков: первый экран, преимущества, услуги, процесс, FAQ и CTA.
- Четыре визуальных пресета (минимализм, яркий, дружелюбный, технологичный): выбранная тема сразу меняет цветовую палитру, кнопки, карточки, геометрию и оформление предпросмотра, а также сохраняется в HTML-экспорте.
- Ручное редактирование ключевых текстов.
- Выгрузка страницы в самостоятельный HTML с адаптивными стилями и базовыми SEO-метатегами.
- Копирование брифа и результата в JSON.
- Обработка типовых ошибок API и тайм-аутов.

## Что это пока НЕ делает

Это MVP, а не законченный коммерческий конструктор: пока нет автоматического сбора и анализа сайтов конкурентов, настоящей генерации/поиска изображений, сохранения нескольких проектов в базе данных, входа пользователей, drag-and-drop редактора и автоматической публикации на хостинг. Не заявляй, что эти функции готовы.

## Требования

- Node.js 20 или новее.
- npm.
- Для локальной генерации — Ollama и скачанная модель, например `qwen3:8b`.

## Запуск на Windows

1. Распакуй архив в удобную папку.
2. Открой эту папку в VS Code. Либо для запуска можно дважды нажать `start.bat` — он создаст `.env`, установит зависимости при первом запуске и стартует приложение.
3. Если запускаешь вручную, открой терминал VS Code (`Terminal → New Terminal`) и выполни:

   ```powershell
   npm install
   Copy-Item .env.example .env
   ```

4. Проверь настройки в `.env`. Для Ollama по умолчанию уже указаны:

   ```dotenv
   LLM_BASE_URL=http://localhost:11434/v1
   LLM_API_KEY=ollama
   LLM_MODEL=qwen3:8b
   ```

   Значение `LLM_API_KEY=ollama` — заглушка для локального сервера, а не настоящий секретный ключ.

5. Убедись, что Ollama работает. Если нужно, загрузи модель:

   ```powershell
   ollama pull qwen3:8b
   ```

   При использовании уже скачанной модели повторно загружать её не нужно. Ollama обычно работает в фоне; при необходимости запусти приложение Ollama.

6. Запусти приложение:

   ```powershell
   npm run dev
   ```

7. Открой **http://localhost:5173**. В одном терминале будут работать frontend и API-сервер. Останавливаются `Ctrl+C`.

> Для локального Ollama проект использует нативный `http://localhost:11434/api/chat`, а не OpenAI-совместимый `/v1/chat/completions`: это нужно, чтобы надёжно отключать thinking у Qwen3 и получать JSON без длинных рассуждений. Запрос ограничен 8192 контекстными токенами и 2400 выходными токенами.
>
> Если модель всё ещё не отвечает, проверь соединение командами в PowerShell:
>
> ```powershell
> ollama list
> Invoke-RestMethod http://localhost:11434/api/tags
> ollama run qwen3:8b "Ответь одним словом: ОК"
> ```
>
> Если последняя команда тоже долго зависает, проблема не в интерфейсе конструктора: модель слишком долго запускается/генерирует на текущих настройках. В `.env` можно указать другую уже установленную модель, затем полностью перезапустить `npm run dev`.

## Подключение удалённого API

В `.env` укажи URL OpenAI-совместимого API, секретный ключ и точное имя поддерживаемой модели:

```dotenv
LLM_BASE_URL=https://api.openai.com/v1
LLM_API_KEY=вставь-свой-ключ-локально
LLM_MODEL=название-доступной-модели
```

Ключ хранится только в локальном `.env`, который исключён из Git через `.gitignore`. Не добавляй `.env` в репозиторий и не вставляй ключ в исходники фронтенда.

## Production-сборка

```powershell
npm run build
npm start
```

Затем открой **http://localhost:3001**. В production-сборке Express отдаёт frontend из папки `dist` и API с того же порта.



## Технологии

React, Vite, JavaScript, Express, Fetch API, OpenAI-compatible Chat Completions API, Ollama, HTML/CSS.
